# Chat and viewport acceptance

Start an owned offline instance with the skill helper. Use fresh OS-light contexts to establish dark default. Toggle light and dark, refreshing after each choice. Inspect both themes at desktop and mobile sizes.

Submit `hello`. Require an ordinary assistant message and no provider call or cards. A useful shopping request must not require an optional budget form. Capture the minimal empty state and ordinary reply.

Submit `I want to buy a powerbank around $30-40.` and then type `SGD.`. Require both bounds, the original objective, automatic research, truthful activity tied to actual transport, and a concise leading answer. Preserve earlier messages across comparisons and preference edits.

Capture the settled recommendation before any manual scroll. Measure its paragraph and first product name against both the viewport and clipping conversation container. Content that exists but has a negative visible position fails. Issue #52 demonstrated that `toBeVisible()` could pass with the leading answer above the mobile viewport. Never repair framing before this check.

Use 1440×1000, 390×844, and a short mobile height. Scroll older and newer history deliberately after the initial-view gate. Require the composer and send action to stay readable, visible, and anchored. Check visible source and edit controls for any rectangle overlap with the floating scroll button. Sample corners and edges as well as the center with hit-testing. Check that the document does not overflow horizontally and that expanded content stays within the conversation.

For composer changes, exercise keyboard focus, Enter, Shift+Enter, and composition events separately. The smoke helper does not establish all keyboard or assistive-technology behavior. Inspect official component provenance in the repository and actual screenshots. Tests do not approve a dashboard or modified generated primitives.
