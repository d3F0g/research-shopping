# Fieldnote verification map

Use a fresh browser context for each independent journey. The offline smoke helper drives the normal v5 application through actual local parsing, fixed synthetic optional fallback proposals and an owned Exa SDK loopback provider. It makes zero OpenAI or Ollama HTTP requests. Useful no-budget requests research immediately; typed currency answers retain their actual question identity. Normal development research and its injected-provider tests have a separate guide. The [skill entrypoint](../SKILL.md) owns launch, doctor, evidence, and cleanup. `scripts/smoke.mjs` records its actual driven chat, evidence and preference subset. It does not replace independent visual judgment. The other paths need their own browser checks or matching tests in `tests/e2e`.

Normal research accepts arbitrary product descriptions and session criteria. Category registries and sample catalogs are confined to historical/test composition. Start with the Exa guide for normal product changes.

## Proof standard

Record the commit, worktree state, feature, entry point, actions, and observed results. Keep screenshots and traces with the report. Every fixture claim, price, and stock state must stay visibly labeled. An API result alone does not prove its UI rendering. A screenshot alone does not prove the action or boundary behavior.

Browser recipes use Playwright's `page`, `context`, and `expect`. Choose stable roles and labels first. Scope `.product-card` and repeated controls to their assistant turn. Global first-card selectors can select a historical result. Do not treat an untested entry point as covered by a different path.

## Package checks

Run `npm test` for domain, API and SDK boundaries. Run `npm run test:e2e` for the real Chromium journeys. Read the current test titles in `tests/e2e/*.spec.ts` before choosing a focused `--grep` pattern. A focused selection does not prove all mapped paths.

Legacy fixture recommendations and exact handoff rejection remain API and domain regressions. Current browser suites cover open intent, budget ranges, unknown requirements, session isolation, stale requests, recovery, source evidence, and comparisons using explicitly injected evidence. Chat changes also need dark-default/theme persistence, ordinary messages, contextual questions/skip, retained turns, obsolete actions and mobile scrolling/composer evidence. Confirm the named tests actually exercise these behaviors on the reviewed candidate instead of inheriting a previous candidate's counts.
