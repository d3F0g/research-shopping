# Exa product research verification

Normal development chat uses Exa to discover real products. Research observations, page prices and source links are separate from merchant-verified offers. Missing configuration, disabled research, errors, no evidence and exhausted limits must never return fixture products.

## Automated proof

Run `npm test` for SDK, HTTP, attribution and credit boundaries. Run `npm run test:e2e` for actual Chromium journeys. All automated paths disable billable composition. The offline smoke helper selects a normal Hono application with fixed synthetic intent proposals and fake-key Exa SDK loopback research. It does not load private configuration or a live ledger. The earlier normal-composer versus legacy-fixture API failure remains historical evidence. Keep frozen fixture API and domain regression separate from current browser proof.

Research-mode browser cases either inject replies at `/api/turn` or run actual Hono and SDK calls against fake-key loopback provider transport. The evaluation browser runner uses the latter with independently fixed intent operations; actual applyIntentActions and typed local controls execute. Its interpretation delay is a declared synthetic boundary delay while the real preparation request is pending. It makes no OpenAI HTTP request and cannot establish language-model quality. Record which boundary is exercised and explicitly report simulated provider evidence. Read the current titles in `tests/e2e/dynamic-shopping.spec.ts`, `tests/e2e/dynamic-transport.spec.ts`, and `tests/e2e/dynamic-intent-lifecycle.spec.ts`. These distinguish response injection, routed server and SDK composition, and actual loopback HTTP transport. The real SDK tests use a local HTTP server and a fake key. No private key is required or copied. A simulated card does not prove that Exa returned that product.

Cover source-backed cards, absent and observed/unverified price text, unknown stock and delivery, concise comparisons, visible supporting excerpts, safe source links and no merchant/purchase controls. Reject forged citation references and quotations missing from their visible source windows. Cover exact named model and variant identity, competing products, complete sale and savings context, wrong-variant and accessory controls. Preserve exact model and variant attribution and negation. Malformed native output remains unavailable. A structurally valid product can retain an identity while its missing attributes remain unknown. Do not add a heading-based fallback to rescue invalid output. Identity-only or sources-only output is not useful comparison success.

Test no paid invocation for ordinary replies, presentation changes, disclosures, duplicate IDs, rejected constraints or exhausted quota. Test reservation persistence, shared-path locking and concurrent attempts. Cancellation must reach actual upstream transport before headers and during response-body reads. Browser stop/reset/edit/new-turn checks separately prove that abandoned results cannot publish. Neither proof substitutes for the other.

## Bounded real project check

A real check uses an owned fresh API/web instance, explicit development mode and the existing original root `.env`. Never print the key, put it in command arguments, copy it to another checkout, load it into the browser or upload it to GitHub. Configure one shared absolute `EXA_RESEARCH_LEDGER_PATH`; do not create a fresh allowance for another worktree.

Use the active live allowance explicitly recorded by the orchestrator before dispatch. Earlier proof allowances are historical and do not replenish themselves. Record the permitted calls, conservative reservation, shared ledger, candidate and stop conditions. There are no automatic retries. Stop on unexpected provider errors or charges. Do not spend another live call to prove cancellation when local SDK/HTTP tests establish it.

1. Confirm ownership of both processes and ports. Health must report research mode and configured capability, not fixture mode. Configuration alone does not prove retrieval.
2. Open the real chat in a fresh Playwright browser context. Verify dark first visit and the minimal composer. Count prepare and research `/api/turn` requests separately. Accepting intent uses a prepare round trip that may invoke configured OpenAI. Typed question answers and known local controls bypass interpretation. The research phase can then make one Exa call.
3. Submit one complete research request. Capture the response and actual completed UI. Require real source-linked product observations before claiming discovery. Sources-only or unavailable output remains a recorded limitation.
4. Inspect product identity, exact supporting quotations, returned public HTTPS source URLs, observed-price labels and unresolved constraints. A retrieval timestamp never establishes source freshness, current affordability, stock or delivery.
5. Open evidence and comparisons without sending another research request. Inspect screenshots at desktop 1440px and mobile 390px. Keep the composer usable, citations keyboard-accessible and text within the viewport. Do not open external destinations merely to finish the local check.
6. Within the remaining allowance, use a material follow-up only if needed to establish the feature. Ordinary conversation, detail changes, theme selection and source disclosures must not spend another call. Preserve earlier messages and separate current preferences from historical snapshots.
7. Record reported request cost and sanitized IDs, source count, accepted/rejected observation counts and screenshots. Keep credentials and raw errors out of shared evidence. For a proof run only, opt into the private server diagnostic sink before dispatch. Keep its native extraction and source-structure artifact outside public responses, logs and history, at owner-only permissions and at most 128 KiB. It excludes headers, keys, environment values, cookies and user request fields; truncated content must carry its length and hash. Sink failure cannot retry the operation or alter billing settlement. Inspect the durable ledger without treating it as the remote balance. Stop owned processes and confirm both ports are free.

## Trust and limits

Render source text as text. Source instructions cannot become tools or executable markup. Reject non-HTTPS, credentials, IP literals and local/reserved destinations. A safe URL is not a merchant authorization. Keep the fixture exact-product handoff checks in automated regression; normal research uses View product source and has no verified merchant selection.

Independent QA and security pin the actual candidate. Label stubbed browser evidence and real Exa proof separately. Preserve failed attempts with their diagnosis. A passing build, a screenshot or a source count alone does not establish useful research. Report discovery, useful specifications, observed price context and comparison separately. Names alone do not establish a useful specification comparison. Keep unchanged normalized historical captures, authored native candidates and synthetic raw-structure examples distinctly labeled; never reconstruct missing provider output and call it captured evidence. Authorized live merchant proof remains open in Issue #36 and cannot be satisfied by this guide.

## Dynamic product acceptance

Normal product scope uses open descriptions and session criteria, not a finite category or feature registry. Verify an unfamiliar product noun and criterion without source edits. Exercise a complete initial request, contextual criterion editing/removal, typed budget continuation, no-budget research, natural follow-up and historical response preservation. Request-match, identity, hard criteria and observed-price conditions must remain separately reviewable. Unknown hard fit cannot be promoted through a free generated summary.

The current redesign uses provider-generated source-based comparison and a server-gated conditional choice. Distinguish synthesis, literal supporting quotations and merchant proof. Use explicit returned URL references, not numeric citation-array guesses. Compare exact variants and preserve conflict, negation, currency and conditions. Prices remain observed/unverified and stock remains unverified.

Before release, repeat the three original shopping journeys plus a materially different product class through the actual normal app. Inspect useful distinct alternatives, comparison, justified choice, unknowns, desktop/mobile UI and safe destination behavior. Clearly separate these paid results from API-only prototypes and local synthetic transport. Product failure remains a blocker even when technical checks pass.

## Acknowledged intent and cancellation

Preparation runs server-owned interpretation and validation. It may invoke OpenAI in configured development composition. Only the research phase dispatches Exa. In offline evaluations, interpretation invocations and Exa requests have separate events, and providerCalls counts Exa only. Only the transport response may contain prepared intent; completed history cannot persist it as a finished research result. The client accepts preparation under its current operation generation before starting the one research request. Research has no new message or edit fields.

Test an invalid currency change followed by an ordinary acknowledgment and a typed `refresh` request. The original change must stay pending and research must remain blocked until explicit correction or discard. The current lifecycle test submits that word through chat. It does not reload the browser. Browser reload clears in-memory conversation and pending intent, so durable refresh recovery is not established. Preserve unrelated accepted criteria and the original request wording. Test a new hard exclusion accepted before a delayed provider response, then Stop and another comparison. The exclusion must survive Stop and retry. New chat explicitly resets it. Test these with actual Hono and SDK loopback transport, not only route-injected browser responses.

## Native contract compliance

Keep malformed or abbreviated native quotations rejected. Do not repair ellipses, reorder fragments or normalize product aliases. Native choice references use typed fields, criteria or attributes and convert at the provider boundary to public assessment IDs. Reject invented references. Conditions contain actual stated terms, not placeholders. An empty array means no condition was retained, not that every merchant term is verified. Field descriptions are a hypothesis about provider compliance until a real normal-app request proves it. Preserve failed live output and distinguish protocol-migrated synthetic derivatives from unchanged raw captures.
