# Live research boundaries

Exa is V2's normal research and structured-answer provider. Web research is not an optional button attached to a synthetic catalog. `src/server/index.ts` composes live research only in development with the required private configuration and shared admission ledger.

The offline helper never loads private environment files or inherits provider, grant, or database variables. Its test-only composition uses a dummy key and owned loopback HTTP. Local substitute calls and synthetic image routes do not prove genuine Exa retrieval or product usefulness.

Live proof is a separate root-coordinated action. Read the current `docs/exa-research.md`, the program ledger, and canonical build-with-exa skill. Run the documented setup command and resolve references from its printed directory. Do not guess request fields or billable allowances.

Require an existing explicit allowance before dispatch. Preserve stopped state, unknown charges, all historical records, and manual-grant baselines. Never create or renew a grant, refund an unknown charge, clear a ledger, automate paid checks, or infer balance from local limits. Grant inspection alone must not reserve usage or call Exa.

A blocked live provider does not block offline implementation or local proof. Record configuration, external retrieval, semantic usefulness, billing, and merchant verification separately. Genuine Exa captures need source-based identity, relevance, specifications, observed-price conditions, safe links, and uncertainty reviewed against the real user request. Stop on unexpected errors or charges.
