## Blocking findings

1. Price attribution is not sufficiently unambiguous. `src/server/exa-research.ts:278-280` recognizes the prefix of a direct price sentence but accepts the remaining text without establishing that it is a whole base-model price. The actual SDK against a local HTTP response accepted each of these as the base model's `page-observed-unverified` price: `Aster Wave 2 costs SGD 99 less than its competitors.`, `Aster Wave 2 costs SGD 99/month.`, and `Aster Wave 2 costs SGD 99 for the Pro edition.` The first is a difference, the second a periodic payment and the third a different edition. Keeping the full quotation and an unverified badge does not establish the promised base-model price association. Preserve these as source context or explicitly typed non-price observations unless an unambiguous price/variant is established.
2. Product category relevance is not established. For a request whose hard category is headphones, the same boundary accepts `Aster Wave 2 is a cotton sweater.` as a structured product fact and creates a source-backed research lead. `src/server/exa-research.ts:264-282` checks name/quote association and some negative features but not the requested product class. The facade then describes structured products as worth comparing. A truthful quote about an explicitly unrelated product must not become a relevant alternative. Retain it only as clearly limited source context or reject it from the structured result.

Both findings have a rerunnable reviewer-authored reproducer in `adversarial.mts` and the actual observable output in `adversarial.json`. It invokes the installed Exa SDK with a fake key against a local HTTP server, one request per case. It never calls Exa. Root has received and accepted these blockers. No production, merchant or live-retrieval conclusion is implied.
