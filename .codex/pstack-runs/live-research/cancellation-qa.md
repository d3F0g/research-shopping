## Original overflow failure

The original owner's screenshot fits within the mobile viewport. Its failed assertion nevertheless measured document width 881 immediately after resizing to 390.

`resize.mjs` reproduces that observation while collecting the browser resize event and 12 following animation frames. All 20 candidate trials measured document width 881 immediately after `setViewportSize` returned. Every subsequent resize-event and animation-frame observation measured document and body width 390. The source-preview positioner then measured left 5, right 325, and width 320. See `resize-observations.json`.

`baseline-resize.mjs` repeated the same experiment against an owned server on exact base `1cf12b2`. All five baseline trials showed the same immediate 881 width and the same settled 390 width. See `baseline-resize-observations.json`. The application has not received the resize event at the immediate observation point. This is an inherited test synchronization race, not a persistent mobile layout regression introduced by the cancellation patch.

The correct test improvement is to wait for the browser resize event and the resulting layout frame, then retain the strict document and body viewport-width assertions. Do not hide overflow, remove the assertion, add a large fixed sleep, or treat a retry as the diagnosis. No such test change was made during this read-only review.
