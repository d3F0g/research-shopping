# V2 architecture decision

## Goal and caller

A shopper submits a complete open request or contextual follow-up. The server retains messages and hard requirements, asks only material missing questions, and runs one bounded Exa Answer request when research is needed. Held comparisons and presentation changes spend nothing.

## Competing shapes

A keeps authoritative conversation state in a typed local reducer. It retains complete objective and contextual text. A small operation union handles money, typed currency questions, exact contextual controls, held comparisons and ordinary messages. Unknown compound text stays intact and unresolved rather than partly applied. Exa synthesizes source-based shopping assessments during one research call.

B asks the same Exa Answer call for proposed conversation state and research. It can interpret broader language, but pays before resolving questions, cannot establish accepted constraints before dispatch and creates rollback/retry coupling. It is not a substitute for an independent conversational model.

Independent architecture and evaluation audits plus application-owner sketch favor A. Root selects A. No separate paid or local interpreter dependency.

| Criterion | A | B |
| --- | --- | --- |
| Hard constraints before dispatch | Typed accepted state and retained exact clauses | Untrusted proposal after paid call |
| Material clarification | Local typed draft preserves both bounds | Can pay before finding ambiguity |
| Held evidence actions | Local and free | Needs separate local path anyway |
| Open product vocabulary | Raw objective accepted without category gate | Provider-dependent |
| Honest evaluation | Actual state before dispatch remains observable | Requires materially different treatment |
| Complexity | One state owner and research boundary | Coupled intent/result rollback |

## Contracts

Session holds revision, immutable message snapshots, active request, pending clarification and active operation identity. Active request holds originalText, source-linked hard/flexible clauses, optional budget bounds and explicit currency, region and presentation preference. Pending currency stores question identity, original request and full numeric draft independently. Historical snapshots do not decode through mutable active state.

Server exposes prepare before research. Preparation returns authoritative accepted context and a stable prepared operation identity. Research runs only after actual client submission, with one SDK operation, persistent admission and cancellation. Existing evidence answers use retained candidate IDs/display order. Every original hard clause remains explicit in source assessment, including unknown outcomes. Server computes eligibility and preserves adverse/conditional/variant context.

No fixed category/feature/brand registry. No broad conversational regex grammar or silent partial compound acceptance. Tiny exact commands and monetary parsing are permitted, raw unrecognized context is preserved. Complete novel objectives can research without optional budget questions.

## Selective integration

Reuse shared conservative quota semantics and SDK transport cancellation. Adapt safe URLs, retained evidence, price qualifiers and source-linked recommendation eligibility. Rewrite conversation reducer, current research contract and minimal official chat UI. Retire normal runtime catalogs, optional inference, overlapping old codecs and obsolete category forms. Preserve old source branches and evaluation historical evidence. Optional accounts adapt reviewed auth and transaction machinery into a nondestructive V2 payload after core journey checks.
